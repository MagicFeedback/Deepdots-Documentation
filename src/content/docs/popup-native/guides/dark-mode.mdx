# Light and dark mode

The popup and the survey inside it take their colours from the survey **Style** in Deepdots. Dark mode works in two ways.

## 1. A dark Style just works

If the Style colours are dark (for example a dark *Survey box background color*), the popup switches to light text by itself: title, close button, progress, questions, answers and buttons. No code change, only a native SDK with dark mode support.

## 2. Follow your app's light or dark mode

If your app has light and dark mode, set the dark colours in Deepdots (**Survey styling › Dark (optional)**) and tell the SDK which mode to use.

Android (Kotlin):

```kotlin
val sdk = DeepdotsPopups().apply {
    initialize(
        InitOptions(
            popupOptions = PopupOptions(publicKey = "<your-public-key>"),
            appearance = Appearance.System, // Light | Dark | System
        )
    )
}

// Your app has its own toggle:
sdk.setAppearance(Appearance.Dark)
```

iOS (Swift):

```swift
popups.setAppearance(appearance: .dark)   // .light, .dark or .system
```

| `appearance` | What you get |
|---|---|
| `null` (default) | Today's behaviour: the Style colours decide. |
| `Light` | Light popup. The Style's dark colours are ignored. |
| `Dark` | Dark popup with the Style's dark colours. Without them it uses the Style colour if it is already dark, or a default dark palette. |
| `System` | Follows the device (Android `uiMode`, iOS `traitCollection`). |

- `setAppearance(null)` goes back to the Style colours. `getAppearance()` returns the current value.
- With `System` the popup frame follows a change while it is open; the survey keeps the mode it opened with.
- On a dark card a light brand button gets dark text, so it stays readable.
- From Swift every `InitOptions` parameter is passed, so the simplest way is `setAppearance(appearance:)` right after `initialize`.
