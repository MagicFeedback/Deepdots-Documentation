<Aside type="note">
`deepdots_popups` `1.0.0` installeres fra git, låst til et release-tag. Den er ikke på pub.dev.
</Aside>

## Krav

| | |
|---|---|
| Flutter | 3.24 eller nyere (Dart 3.5). Builds tjekkes på hver stabil udgivelse fra 3.24 til 3.47. |
| Android | minSdk 24, compileSdk 36. Android Gradle plugin 8.9.1, Gradle 8.11.1 og Kotlin 2.1 eller nyere. |
| iOS | 13.0 eller nyere. Swift Package Manager kræver Flutter 3.41 eller nyere; CocoaPods virker på alle understøttede versioner. |
| Native SDK | `0.7.9`, hentes ind af pluginet (Maven Central på Android; Swift Package Manager eller CocoaPods på iOS) |

Apps oprettet med en ældre Flutter-skabelon kan have brug for et par ændringer: se [Android](#3-opsæt-android) og [iOS](#4-opsæt-ios) nedenfor. Hvis din app er på en Flutter-version ældre end 3.24, så sig det til din Deepdots-kontakt.

## 1. Repository

Pluginets repository er offentligt ([MagicFeedback/deepdots-popup-flutter-sdk](https://github.com/MagicFeedback/deepdots-popup-flutter-sdk), Apache License 2.0): der skal ikke bedes om adgang, og der kræves ingen git-credentials.

## 2. Tilføj afhængigheden

Lås afhængigheden til release-tagget:

```yaml
# pubspec.yaml
dependencies:
  deepdots_popups:
    git:
      url: https://github.com/MagicFeedback/deepdots-popup-flutter-sdk.git
      ref: v1.0.0
```

```bash
flutter pub get
```

Lås altid `ref` til et tag. For at opdatere skal du ændre tagget og køre `flutter pub get` igen.

## 3. Opsæt Android

Apps oprettet med Flutter 3.35 eller nyere behøver ikke mere:

- Det native SDK kommer fra Maven Central. `mavenCentral()` skal være blandt dine repositories, som det er i et standard-Flutter-projekt.
- Pluginet erklærer `INTERNET`-tilladelsen, som Flutter kun tilføjer til debug- og profile-builds. Uden den kunne et release-build ikke nå Deepdots. Du behøver ikke selv tilføje den.
- Enhver `Activity` virker, inklusive standard-`FlutterActivity`.

### Apps oprettet med Flutter 3.24 til 3.32

Deres skabelon bruger en ældre Android-toolchain, end det native SDK's biblioteker kræver. Opgradér den:

I `android/settings.gradle` eller `android/settings.gradle.kts`:

```kotlin
id("com.android.application") version "8.9.1" apply false       // eller nyere
id("org.jetbrains.kotlin.android") version "2.1.21" apply false  // 2.1 eller nyere
```

I `android/gradle/wrapper/gradle-wrapper.properties`, Gradle 8.11.1 eller nyere:

```properties
distributionUrl=https\://services.gradle.org/distributions/gradle-8.11.1-all.zip
```

I `android/app/build.gradle` eller `android/app/build.gradle.kts`, inde i `android { ... }`:

```kotlin
compileSdk = 36
defaultConfig {
    minSdk = 24
}
```

Uden disse ændringer stopper buildet med en besked, der nævner den manglende version, for eksempel "requires Android Gradle plugin 8.9.1 or higher" eller "compiled with an incompatible version of Kotlin".

## 4. Opsæt iOS

Din app skal have iOS 13.0 eller nyere som target. Apps oprettet med Flutter 3.32 eller ældre har 12.0: hæv **Minimum Deployments** til 13.0 i Xcode (Runner-target, fanen General) og, med CocoaPods, sæt `platform :ios, '13.0'` øverst i `ios/Podfile`.

Flutter bygger iOS-plugins med Swift Package Manager, når det er slået til, og ellers med CocoaPods. Begge virker, men Swift Package Manager kræver Flutter 3.41 eller nyere. På en ældre Flutter med Swift Package Manager slået til fejler buildet med "The folder FlutterFramework doesn't exist": slå det fra med `flutter config --no-enable-swift-package-manager`, så bruger appen CocoaPods.

Det native SDK leveres uden et `x86_64`-simulator-slice, så Intel-simulatorarkitekturen skal udelukkes. Uden denne indstilling virker `flutter run` på en Apple Silicon-simulator stadig, men `flutter build ios --simulator` fejler ved linkning.

<Tabs>
  <TabItem label="Swift Package Manager">
    Tilføj denne linje i slutningen af både `ios/Flutter/Debug.xcconfig` og `ios/Flutter/Release.xcconfig`:

    ```text
    EXCLUDED_ARCHS[sdk=iphonesimulator*] = i386 x86_64
    ```
  </TabItem>
  <TabItem label="CocoaPods">
    Tilføj dette til `post_install`-blokken i `ios/Podfile`:

    ```ruby
    installer.aggregate_targets.each do |aggregate|
      aggregate.user_project.native_targets.each do |target|
        target.build_configurations.each do |config|
          config.build_settings['EXCLUDED_ARCHS[sdk=iphonesimulator*]'] = 'i386 x86_64'
        end
      end
      aggregate.user_project.save
    end
    ```

    `pod install` downloader det native SDK's XCFramework og tjekker dets sha256.
  </TabItem>
</Tabs>
