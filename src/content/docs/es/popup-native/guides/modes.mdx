# Cómo se cargan los popups

Los popups se **gestionan siempre en Deepdots y se cargan desde la API en tiempo de ejecución**. No hay un modo en cliente, y la app host nunca define popups a mano. Gestionas todo lo relativo a un popup en Deepdots, y el SDK lo carga por ti.

## Cómo funciona

Las definiciones, los copys, los triggers, la segmentación y los cooldowns viven todos en Deepdots. En tiempo de ejecución el SDK los carga usando tu `publicKey`:

```text
/sdk/{publicKey}/popups
```

El trabajo de la app host es simplemente inicializar el SDK y reaccionar a sus eventos. No hay ningún payload de popup que ensamblar o enviar en la build de la app.

## Configuración mínima

```kotlin
val options = InitOptions(
    debug = true,                              // solo logs del SDK — NO cambia el backend
    environment = Environment.Development,     // omite (o usa Environment.Production) para apuntar a prod
    popupOptions = PopupOptions(
        publicKey = "<your-public-key>"
    ),
    autoLaunch = true,
    provideLang = { "en" },
    metadata = mapOf("userId" to "demo-user")
)

val sdk = DeepdotsPopups().apply {
    initialize(options)
    setPath("/home")
}
```

Lo único imprescindible para cargar popups es un `publicKey` válido en `PopupOptions`.

## ¿Por qué no hay definiciones en cliente?

Definir popups en la app repartiría la propiedad de la experiencia y ataría cada cambio a una release. Una única fuente de verdad en Deepdots permite a los equipos de producto, marketing y customer success cambiar copys, segmentación y triggers sin publicar una nueva build.
