# Installation

Este repositorio expone dos caminos de consumo principales:

- Android vía Maven Central con `com.deepdots.sdk:shared-android`
- iOS vía Swift Package Manager con el manifiesto de paquete binario `DeepdotsSDK`

## Requisitos

- Las apps Android compilan contra Java 17 en este repositorio
- Las apps de ejemplo Android usan `minSdk = 24`
- La distribución iOS apunta a **iOS 13+**
- El namespace del módulo del SDK compartido es `com.deepdots.sdk`

## Android

Añade la dependencia publicada:

```kotlin
dependencies {
    implementation("com.deepdots.sdk:shared-android:0.5.0")
}
```

La app de ejemplo de Android de este repositorio usa exactamente esa coordenada.

### Comandos de ejemplo en Android

```bash
./gradlew :example-android:assembleDebug
./gradlew :example-android:installDebug
```

## iOS

El SDK se distribuye como paquete Swift binario desde [`MagicFeedback/DeepdotsSDK-SPM`](https://github.com/MagicFeedback/DeepdotsSDK-SPM). Expone el producto de librería `DeepdotsSDK`.

En Xcode, ve a **File → Add Package Dependencies…**, introduce la URL del repositorio y elige la versión `0.5.0`:

```text
https://github.com/MagicFeedback/DeepdotsSDK-SPM
```

O, en un `Package.swift`:

```swift
dependencies: [
    .package(url: "https://github.com/MagicFeedback/DeepdotsSDK-SPM", from: "0.5.0")
],
targets: [
    .target(name: "YourApp", dependencies: [
        .product(name: "DeepdotsSDK", package: "DeepdotsSDK-SPM")
    ])
]
```

El manifiesto del paquete es binario:

```swift
// swift-tools-version: 5.7
import PackageDescription

let package = Package(
    name: "DeepdotsSDK",
    platforms: [
        .iOS(.v13)
    ],
    products: [
        .library(name: "DeepdotsSDK", targets: ["DeepdotsSDK"])
    ]
)
```

### Flujo del ejemplo iOS en este repositorio

El proyecto demo de iOS resuelve un paquete local desde `spm-local/`. Si falta el XCFramework local, regenéralo primero:

```bash
./run_ios_example.sh
```

Para resolver y compilar desde las herramientas de Xcode:

```bash
cd iosApp
xcodebuild -resolvePackageDependencies -project iosApp.xcodeproj -scheme iosApp -destination 'generic/platform=iOS Simulator'
xcodebuild -scheme iosApp -project iosApp.xcodeproj -destination 'platform=iOS Simulator,name=iPhone 16e' build
```

## Detalles de empaquetado públicos frente a internos

- Detalle público de consumo: la coordenada de dependencia de Android y los nombres del paquete/producto SPM de iOS
- Detalle de mantenimiento: los scripts de release en `scripts/prepare_sdk_release.sh`, `scripts/prepare_spm_release.sh` y `scripts/prepare_maven_upload_zip.sh`

Esos scripts de mantenimiento forman parte del repositorio, pero están orientados al tooling de release, no a los pasos de integración del usuario final.
